## Title
Write Stage 4 test: panel updates correctly during runtime iterations with repeatable effects

## Description
Once the root cause of the panel-not-updating issue is understood (TASK-001) and the repeatable effect self-stop test is in place (TASK-002), this task creates a comprehensive Stage 4 test that validates panel content updates driven by repeatable effects.

**IMPORTANT CONSTRAINT: The `application/client/solution/Test/` directory is restricted.** Agents cannot edit files there directly. This task file is a specification for the implementer (a human developer).

### What the test must verify:
1. A repeatable effect that modifies entity state (e.g., increments a number each iteration) is registered.
2. A panel displays the entity-bound value (e.g., `entityNumberValue` content type).
3. Across multiple `RuntimeInterop.RunIteration()` calls, the panel content updates to reflect the new entity value each iteration.
4. Once the repeatable effect self-stops (per TASK-002 logic), subsequent iterations do NOT change the panel value.

### Where to create the test:
New directory: `application/client/solution/Test/Stage_4/PanelUpdateWithRepeatableEffect/`

### Files the implementer needs to create:
1. `module/manifest.json` — module manifest
2. `module/index.js` — module entrypoint that:
   - Registers an entity with a number value (e.g., `numberKey: 0`)
   - Registers a repeatable effect that increments `numberKey` by 1 each iteration, stopping after N iterations
   - Registers a panel with `entityNumberValue` content bound to that entity/number key
3. `TestClass.cs` — GdUnit4 test class:
   - Loads the test scene
   - Asserts initial panel content is "0"
   - Calls `RunIteration()` and asserts panel updates to "1", then "2", etc.
   - After N iterations, calls `RunIteration()` again and asserts the value remains unchanged (effect has self-stopped)

### Reference patterns:
- `Stage_4/EntityNumberValueUpdate/TestClass.cs` — panel content update assertion pattern (`AssertPanelThat(...).HasContentText(...)`)
- The repeatable effect API from `application/suite/types/Effect.d.ts`

## Acceptance Criteria

- The test fails when panel content does NOT update (reproducing the reported bug)
- The test confirms the panel value stabilizes after the repeatable effect self-stops
