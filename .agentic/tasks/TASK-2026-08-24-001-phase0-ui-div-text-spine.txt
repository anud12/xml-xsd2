## Title
Phase 0 (spine): one ui.div + one ui.text flows QuickJS -> delta -> Godot node

## Description
Plan reference: plans/ui-div-layer.md, "Phase 0 — Engine of record + transport + spine" and
Verification item 1 ("Spine (P0): one div+text renders QuickJS -> delta -> Godot").

Goal: prove the end-to-end spine with the SMALLEST possible slice before building up the full
model. Exactly one div containing exactly one text, evaluated by Rust/QuickJS (the engine of
record), diffed into an id-keyed delta, transported over the new FFI seam, and rendered as a
real Godot node on screen. No layout engine, no grid, no state, no field leaves in this task.

Resolved open questions baked in:
- Engine of record = Rust/QuickJS (application/runtime). C#/Jint's UI host is NOT the engine.
- The canonical .ui layer lives at application/ui/ (top-level, sibling of client/runtime/suite).

Work items (keep the delta format minimal — it will grow in later tasks):
1. Scaffold the canonical .ui layer directory:
   - application/ui/ui/ with host.js — builds hostApi.ui.* over a transport seam. For this
     task the transport is a set of plain functions (registerNode, emitDelta, readClientState,
     resolveResource) stubbed on globalThis; the real QuickJS implementations land in task 002.
   - application/ui/types/ with a minimal ui.d.ts covering just ui.div + ui.text for now.
   - application/ui/test/ — engine-agnostic JS tests (run under node; the suite has
     typescript available, keep it plain JS for engine-agnosticism).
2. Rust side (application/runtime/src/):
   - New module (e.g. src/ui/): a UiNode model (id, kind div|text, text value, parent id),
     a UiState (HashMap<String, UiNode> + insertion order) with an id-diff producing a delta:
     Vec<UiDelta> where UiDelta = Add{node} | Update{node} | Remove{id}.
   - Wire a minimal host API into the QuickJS contexts used by module extraction
     (src/js_executor/extract.rs -> get_host_api_script(), plus the sim host builders in
     src/js_executor/sim_entry.rs / sim_invoke.rs / extract_invoke.rs which each inline a
     hostApi object — all four must expose the same ui surface): hostApi.ui.div(id, opts,
     children) and hostApi.ui.text(id, value) that push JSON node descriptors onto
     globalThis.__uiNodes; and extract_declarations (src/js_host_api/script_extract.rs +
     src/js_host_api/mod.rs Declarations struct) picks them up into the declarations
     pipeline so they flow through apply_declarations (src/module/declarations/mod.rs) into
     the new UI state.
   - FFI transport seam in src/ffi_mod/: a runtime_fetch_ui_state() -> *mut c_char returning
     the full UI tree as JSON (for initial paint) and a runtime_ui_dirty() -> bool (or a
     fetch-ui-delta variant) so the C# client pulls id-keyed deltas. Follow the existing
     c_char pointer + runtime_free_string conventions (src/ffi_mod/misc/free_string.rs).
     Export the symbols in src/ffi_mod.rs.
3. C# side (application/client/solution/Sources/):
   - Runtime/RuntimeInterop.cs: DllImport wrappers for the new FFI functions.
   - UI/: a new minimal delta applier (e.g. UiDeltaApplier.cs + one Godot.Control per node):
     create/update/destroy Controls by node id. Text nodes become a Label; div nodes become a
     Control. Keep it dumb — no layout logic yet (fixed offsets fine for the spine).
   - Scenes/Game.cs: after archive load, build the UI root from the initial fetch and apply
     deltas after each RuntimeInterop.RunIteration() in the 40 ms loop thread (marshal to the
     main thread via Callable/Messages or a queue drained in _Process).
4. Demo module: a small throwaway module (NOT under the restricted Test/ directory — put it in
   a scratch location such as application/client/solution/SpineModule/ or drive it from the
   Rust test harness) that declares:
       ui.div("spine-div", {}, [ ui.text("spine-text", "spine") ])
   and the text value can be a second literal so the delta update path is exercised by a
   trivial effect if convenient — but a static spine also satisfies this task.
