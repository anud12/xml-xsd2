Write Stage 4 test: repeatable effect can stop by itself

## Description
The note states: "To be able to run an automated test to check it i first need to add a test to test if a repeateable effect can stop by itself" and "Write test in stage 4."

This task requires creating a new Stage 4 test module that validates the repeatable/reoccurring effect lifecycle — specifically that an effect with `reoccurAfterMs` and `isReoccuranceApplicable` hooks fires a finite number of times and then self-terminates.

**IMPORTANT CONSTRAINT: The `application/client/solution/Test/` directory is restricted.** Agents cannot edit files there directly. This task file is a specification for the implementer (a human developer) who will write the actual test code.

### What the test must verify:
1. An effect registered with `reoccurAfterMs` returning a positive delay schedules itself for re-execution.
2. An effect registered with `isReoccuranceApplicable` returning a false `ConditionExpression` stops after the current execution (self-termination).
3. The effect fires the expected number of times and then does NOT fire on subsequent `RunIteration()` calls.

### Where to create the test:
New directory: `application/client/solution/Test/Stage_4/RepeatableEffectSelfStop/`

### Files the implementer needs to create:
1. `module/manifest.json` — module manifest (follow pattern from existing Stage 4 modules)
2. `module/index.js` — module entrypoint that:
   - Registers an effect with `reoccurAfterMs` that returns a delay for the first N executions
   - Registers `isReoccuranceApplicable` that returns `true` for executions 1..N and `false` thereafter
   - Uses `hostApi.log(...)` to log each execution so the test can assert via `AssertRuntimeOutputContains`
   - Registers a panel for the test scene
3. `TestClass.cs` — GdUnit4 test class following the existing Stage 4 pattern:
   - Loads the test scene via `LoadTestScene()`
   - Calls `RuntimeInterop.RunIteration()` multiple times
   - Asserts that effect log lines appear for exactly N iterations
   - Asserts that after N iterations, the effect log lines do NOT appear

### Reference patterns:
- `Stage_4/EntityNumberValueUpdate/TestClass.cs` — standard Stage 4 test structure
- `Stage_3/EmitActionAndTriggerOnClick/TestClass.cs` — shows how effects are tested (fire on RunIteration, stop after one iteration for non-repeatable)
