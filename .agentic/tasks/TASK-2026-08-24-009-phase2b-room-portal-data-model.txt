## Title
Phase 2b (Layer A): Room/Portal data model in Rust state + setRoom/setPortal host API + declaration pipeline

## Description
Plan reference: plans/ui-div-layer.md, "Data Model: the Map (single map, room graph,
runtime-extensible)" and Phase 2b bullet 1 ("Data model (Layer A): add Room/Portal declaration
types — Rust state (src/state), declaration application (src/module/declarations),
setRoom/setPortal host API (both engines' host scripts), and manifest/declaration plumbing").

This task is DATA ONLY — no rendering (the canvas node comes in task 010). Rooms and portals
are first-class declarations flowing through the same declaration + per-tick evaluation +
id-reconciliation pipeline as entities/containers, which makes them runtime-mutable and
delta-synced automatically (the plan's load-bearing decision).

Data model (verbatim from the plan):
- Room { id, terrain, origin {x, y}, rotation, points: [{x, y} x n] }
  * points are LOCAL to the room; (0,0) is the room's origin = the room's CENTER.
  * points must be an ordered CONVEX polygon (validated at declaration: all consecutive edge
    cross-products share a sign; reject non-convex with a clear error log).
  * world transform: world_point = origin + R(rotation) * local_point (rotation in radians
    about the origin).
  * Edge i is implicit: points[i] -> points[(i+1) % n].
- Portal { id, from: { room, edge, range {t0, t1} }, to: { room, edge, range {t0, t1} } }
  * edge = index into the room's points; range = 0..1 span along the edge.
  * Validate: edge indices in range, 0 <= t0 < t1 <= 1, from.room / to.room exist at
    declaration time (or defer to first use with a logged warning — decide, document, test).
